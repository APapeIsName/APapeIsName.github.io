오늘은 저번에 하던 곳부터 다시 시작한다.

$PATH 라는 변수에 미리 디렉토리 위치들을 저장해둘 수 있다. 
```
echo $PATH
```
로 작성하게 되면 자신이 설정해둔 환경변수들이 콜론(:)을 통해 구분지어 리스트 형태로 나타나게 된다. 쉘은 명령을 입력할 때 이를 사용한다. 예를 들어 `date`를 입력하게 되면, 쉘은 date라는 명령어를 처리하기 위해 미리 등록된 환경변수들을 하나씩 확인하게 된다. 이때 보통 `/usr/bin` 같이 입력돼 있는데 이 뒤에 /date 라는 파일을 통해 `date`라는 명령이 실행된다.

그래서 `/usr/bin/date` 처럼 입력하게 되면 `date`와 똑같은 결과가 나온다. 이런 실제 경로를 아는 방법은 `which`이다. 
```
which date
```
which 의 뜻은 "어느" 라는 뜻으로, date가 어느 곳에서 왔냐고 묻는 것이다. 위처럼 입력했을 때 저 명령어를 입력했을 때 발생하는 동작, 즉, 가장 먼저 발생할 수 있도록 하는 경로로 안내한다. 이 말은 무엇이냐면, date 라는 명령어는 여러 디렉토리에 파일로 존재할 수 있지만 우리가 date 라고 입력했을 때는 환경변수에서 맨 앞에 있는 것부터 읽어들여 처리하기 때문에, 우리는 결국 `/usr/bin/date`의 date 명령어가 실행된다는 뜻이다.

만약 모든 경로에 있는 해당 명령어를 찾아보고 싶다면 `which -a date`를 사용하면 된다. which를 사용하게 되면 몇 가지 특이한 것들이 나온다. 첫째로 builtin 명령어라는 것이다. `which cd`를 입력하게 되면 cd는 빌트인 명령어라고 안내된다. 빌트인 명령어는 곧 쉘 프로그램 안에 코드로 미리 들어있는 것으로, 만약 빌트인 명령어일 경우에는 쉘이 파일을 찾기 전에 알아서 처리한다.

그리고 alias 라는 것도 존재한다. alias는 별칭으로, 어려운 명령어들을 미리 설정해서 짧게 칠 수 있게 해준다. 이 alias는 쉘에서 먼저 찾아서 처리하게 해주는 두 번째 경우이다. alias의 대표적 예시는 `grep`이다. 이 명령어는 파일에서 특정 단어를 정규표현식을 통해 찾을 수 있게 해준다. grep의 단어 뜻은 본래 g/re/p 로 입력하던 방식에서 유래했는데, g는 global, re는 정규표현식, p는 print라는 의미로, 전체에서 정규표현식을 통해 찾아라 라는 의미가 된다. 즉, "파일 전체를 뒤져서 정규표현식에 맞는 내용을 찾아내라"는 명령어이다.

```
grep hi a.txt
```

위 명령어처럼 입력하면 a.txt에서 hi를 찾는다. 즉 `grep [찾을 정규표현식 문장] [파일]` 형태이다. 여기서 중요한 한 가지는 [파일] 부분을 생략해도 된다는 것이다. 그렇게 되면 grep은 입력을 받아둘 수 있게 열어둔다. 이 입력창에 "hi everybody" 라고 입력하면 이를 바로 찾아내게 된다. 이것을 잘 활용하면 다음과 같은 방법도 써볼 수 있다.

```
cat a.txt | grep hi
```

여기서 알아두어야 할 것은 2가지이다. 첫째로 `cat`이다. 이 명령어는 뒤에 있는 인자에 들어온 파일을 그대로 읽어 출력한다. 둘째는 파이프이다. 파이프라는 것은 커널에서 출력을 입력으로 이어주는 역할을 맡는다. 우리가 배관을 보면 한쪽으로 들어가 한쪽으로 나오는 것처럼 출력을 그대로 새로운 입력으로 이어주는 역할을 하는 셈이다. 그리고 이것을 쉘에서 쓸 수 있게 만든 것이 `|`이다. 즉, 이렇게 된다. cat 으로 확인한 a.txt의 내용을 한 줄 읽으면 grep이 hi를 찾는다. 이것을 계속 반복해 cat 후 grep을 하는 것과 같은 효과를 낸다.

중요한 것은 파이프의 구조이다. 파이프는 커널이 메모리 버퍼를 사용해서 데이터 입출력을 관리한다. 이때, cat과 grep은 거의 동시에 움직이기에 cat의 입력이 바로 grep으로 나오게 된다. cat이 출력한 문자를 파이프가 입력으로 받고 이를 grep이 줄마다 처리하게 된다. 그래서 cat과 그랩을 합치면 마치 그것이 바로바로 나오는 것처럼 보인다. 하지만 이 뒤에는 파이프라는 메모리 버퍼가 숨겨져 있다. 메모리 버퍼에 관해서는 뒤에 나올 CS:APP에서 더 이야기해보도록 하자.

또한 grep은 재귀 호출이 가능하다. 이것이 무슨 의미냐면 `grep -r hi` 을 사용해 현재 자신의 디렉토리 기준으로 자신의 자식 디렉토리들을 전부 뒤져서 내가 찾는 단어인 hi가 있는지 찾아본다는 의미이다. 항상 AI가 치는 쉘 명령어들을 보면 어떻게 이걸 이렇게 빨리 찾지 싶었는데 grep -r 과 AI의 추론을 합쳐서 쓴 에이전트의 능력이라는 생각이 든다.

그 외에도 `ls`는 list의 약자로 현재 디렉토리 하위에 어떤 것들이 있는지 리스트를 보여준다. 이때 .으로 시작하는 숨김 파일들까지 전부 보려면 `ls -a`를 입력하면 된다. 여기서 -a는 all이라는 의미이다. 또한 `sort`는 안에 있는 내용들을 정렬해준다. sort의 뜻과 알맞다. 이때 정렬 방법은 --help에 나와 있으니 직접 고를 수 있다.  `uniq`는 연속되어 줄바꿈 돼 있는 것들 중 중복을 없애서 표현해준다. 이것도 unique의 뜻과 알맞다. 3이 연속으로 줄바꿈돼 적혀 있으면 3은 한번만 표시해준다. 대신 중간에 4가 들어가 있으면 3 4 3 순서대로 보여준다. 각각 정리해서 출력하고 싶을 때 사용하면 좋을 듯하다. 참고로 sort에는 중복을 없애서 정렬할 수도 있다.

`head`와 `tail`도 존재한다. 그 뜻에서 보이듯 머리와 꼬리를 본다는 것인데, head는 파일의 첫 부분, tail은 파일의 끝 부분을 보여준다. 이때 `head -n3`처럼 입력하면 앞에서 3개를 보여주게 된다. 이는 tail도 동일시하게 적용되는 부분으로, `tail -n4`처럼 입력하면 뒤에서 4개를 보여주게 된다. 이는 곧 파일의 최신 혹은 가장 오래된 부분을 볼 수 있게 할 수 있다. 예를 들면 로그와 같은 것들에 적용해볼 수 있겠다.

아쉽게도 이번주에 모든 걸 다 끝내지 못했다. 예상치 못한 약속이 생기기도 했고, 내가 일부러 궁금한 것들을 놓치지 않으려 했다. 아마 다음주에 이 내용이 마무리되고 조금씩 밀릴 수도 있을 것 같다. 하지만 이런 방식이 그렇게 나쁘다고 생각하지 않는다. 오히려 지금 커널에 대해 조금씩 다가가며 그때 왜 그랬는지 더 이해가 잘 될 수도 있기 때문이다. 처음 시작은 느리더라도 오래 기억하고 내가 재밌게 할 수 있다면 그것이 나는 제일 좋다.
