마지막이다. 

쉘은 스크립트 언어로, if 조건문이나 while, for 반복문도 지원한다. 

```
if grep 2026 thedate.txt; then echo "it's 2026"; fi
```

위처럼 입력하면 grep을 통해 thedate.txt에서 2026을 찾아보고, if가 그 결과를 3가지로 나눈다. 0번은 출력 성공, 1번은 실패, 2번은 오류 발생이다. 이때 0번이 나오게 되면 ; 이후에 적힌 then 뒤의 명령을 실행하게 된다. 따라서 "it's 2026" 같은 문장이 나오게 되는 것이다. 이 뒤에는 fi가 있다. if문의 끝을 알리는 방법이다.

만약 없다면 else를 통해 처리할 수 있다. 1, 2번 중 하나가 나온다면

```
if grep 2026 thedate.txt; then echo "it's 2026"; else echo "it's not 2026..."; fi
```

위 명령처럼 입력했을 때 "it's not 2026..." 이라고 뜰 것이다. if 조건에 단순한 비교 같은 걸 하고 싶다면 `test`를 사용하면 된다. 이것은 마치 일반적인 프로그래밍 언어에서의 ( ) 안의 조건을 보여주는데, 셸에서는 [ ] 안에 넣는 걸로 이를 대신할 수도 있다. test와 []는 완벽히 같다.

```
if [ "you" = "me" ]; then echo "you are me"; else echo "you are not me"; fi
```

위처럼 썼을 때 "you" 라는 단어와 "me" 라는 단어가 다르기에 else 뒤에 있는 "you are not me"가 출력된다. 

앞서 말했듯 while 과 for 도 존재한다. while의 경우에는 그것이 옳다면 반복적으로 실행한다. 

```
while grep 2026 thedate.txt; do echo "it's 2026"; done
```
실행하게 되면 grep의 출력과 do 이후 echo 의 출력이 반복적으로 나타난다. 여기에 do 이후 done 이전에 `sleep 10`을 추가하면 10초의 텀을 갖고 반복하게 된다. for문도 다르지 않다. 

```
for varname in a b c d; echo "$varname";
```
약간 다른 점이 있다면 do 와 done을 생략할 수 있다는 점 정도겠다. 어쨌든 위처럼 입력하면 varname 이라는 변수가 a b c d를 한 번씩 돌고 echo 에 한 번씩 출력된다. 만약에 이를 좀 더 잘 사용하고 싶다면, 그러니까 1 2 3 4 ... 같은 걸 만들고 싶다면 `seq` 이라는 명령어를 활용해볼 수 있다. 이때, 셸 내부에 프로그램을 불러와 그 값만을 출력시키기 위해 특수한 방법을 활용해야 한다.

```
for varname in $(seq 1 10); echo "$varname";
```

$() 는 앞서 말했듯 셸에서 프로그램을 불러와 출력시키기 위한 방법이다. 이때, 이것과 파이프는 마치 유사한 것처럼 보이는데 다르다. $()는 인자이며, 파이프는 데이터 입력이다. 인자와 데이터 입력이 같아보이지만 다르다. 인자는 프로그램이 시작할 때 고정된 곳에 위치한다. 반면, 데이터 입력은 사용자나 다른 프로그램과 같이 데이터를 입력받는다. 즉, $()는 프로그램에 고정돼 값이 변경된다면, 데이터 입력은 이전 글들에서 이야기했던 파일 디스크립터가 지정해준 표준 입력 0번에 값을 넣어준다. 

셸로 명령어를 작성하다보면 길어질 수 있다. 이럴 경우에는 직접 셸 파일을 만들어 프로그램을 만들어보는 방법을 써볼 수 있다. 직접 쓰기보다는 우선 예제를 통해 확인하자.

```
#!/bin/bash
set -euo pipefail

# Start CPU stress in background
stress --cpu 8 &
STRESS_PID=$!

# Setup log file
LOGFILE="test_runs_$(date +%s).log"
echo "Logging to $LOGFILE"

# Run tests until one fails
RUN=1
while cargo test my_test > "$LOGFILE" 2>&1; do
    echo "Run $RUN passed"
    ((RUN++))
done

# Cleanup and report
kill $STRESS_PID
echo "Test failed on run $RUN"
echo "Last 20 lines of output:"
tail -n 20 "$LOGFILE"
echo "Full log: $LOGFILE"
```
이 파일은 부하 테스트와 관련된 테스트 파일(./script.sh)이다. 다른 것보다 주목해야 할 점은 맨 위에 있는 `#!/bin/bash`이다. 이는 셸에게 읽히지 않고 커널에게 읽히는 주석이다. 셸은 #를 주석으로 처리하기 때문에 이를 알지 못한다. 그리고 그대로 커널에게 이 프로그램이 읽힌다. 이때 커널은 `#!/bin/bash`를 읽고 이것을 별도로 처리한다. 이는 처리할 대상을 '/bin/bash ./script.sh' 라는 경로로 바꾼다는 의미가 된다. 그후 커널이 이 '/bin/bash'를 실행하고, 실행된 bash는 이 스크립트의 내용을 처리하게 된다.

이외에도 권한과 관련된 내용이 있었는데, 이 내용에 대해 깊게 다루지는 않아 넘어가도록 한다.

이제 git으로 간다.
