MIT는 학생들이 강의를 들을 때 명령이나 버전 관리에 취약하다는 걸 느끼고 Missing Semester를 만들었다.요즘 같은 AI 시대에 기본기 다지기를 하기 좋다고 판단해 Shell과 Git을 공부하고, 이후 사이드 프로젝트로 이어 진행할 예정이다.

우리는 터미널을 열어서 명령을 칠 수 있다. 보통 이럴 때 쓰는 언어를 셸 언어라고 표현하는데, 셸 언어란 것은 bash, zsh, powershell 등 다양하게 존재한다. 강의에서는 bash, zsh를 다룬다. 
먼저 다룬 내용은 **date** 다. date 는 간단하게 쳐볼 수 있는 명령어로, 입력 후 엔터를 치면 현재 시간이 나온다. date 처럼 단순히 입력 후 끝나는 게 있는가 하면 인자를 받아서 처리할 수 있는 명령어도 있다. 대표적으로 나온 예시가 **echo**이다. 

echo는 터미널에 문자열을 출력할 수 있다. 이때 인자를 받을 수 있는데, 예를 들면 다음과 같다.
```
echo hello world
```
위를 입력하면 터미널에는 hello world 라고 출력된다. echo 뒤 인자는 문자열로 표시된다. 다만, 이것이 hello world 로 나오게 된 이유가 hello 와 world 사이 띄어쓰기 문자로 받아들여서 그런 것이 아니라, 두 개의 인자를 받아서 처리하는 방식이 그러하기 때문이다.

이를 잘 보여주기 위해서는 hello 와 world 사이를 길게 떨어뜨려보면 된다. 일반적으로 기대하는 값은 
```
hello               world
```
와 같이 길게 떨어진 형태이다. 하지만 놀랍게도 `hello world` 처럼 하나의 띄어쓰기만 포함된다. echo가 인자를 여러 개 받아서 처리한다는 증거이다. 그러면 띄어쓰기를 여러 개 넣고 싶으면 어떻게 해야 할까?

```
echo "hello               world"
````

위와 같이 쌍따옴표를 쓰거나, 따옴표를 쓰게 되면 그것을 하나의 인자로 인식한다. 이때 주의해야 할 것은 이스케이프와 관련된 이슈다. 즉, 내가 만약 쌍따옴표를 내용으로 쓰고 싶다면 그것을 이스케이프 처리하거나 앞 부분을 따옴표로 묶어야 한다. 이것은 충분히 일어날 수 있는 일이니 별도 처리가 필요하다.

이런 echo의 인자 처리 방법에 대해서 **man**이라는 명령어로 확인해볼 수 있다. 
```
man echo
```
이는 매뉴얼의 약자로, 각 명령의 매뉴얼에 대해 소개할 수 있다. 그리고 bash 도 `man bash` 를 통해 매뉴얼을 볼 수 있다. 혹은 뒤에 `--help`를 붙여도 매뉴얼과 비슷한 도움말들을 확인할 수 있다.

다음은 **cd**이다. cd는 조금 특별한 명령어다. cd는 change directory 의 약자로, 디렉토리를 옮겨간다는 뜻이다. 이는 즉, 내가 지금 작업할 디렉토리를 옮기겠다는 의미가 된다. cd의 기본 문법은 다음처럼 이뤄진다.

```
cd /bin
```

위 명령을 입력하면 /bin 이라는 폴더로 이동한다. 여기서 /는 디렉토리 구분자이며, bin은 디렉토리 이름이다. 그리고 / 의 앞에 아무 디렉토리 없는 형태라면 최상위 디렉토리로 이동한다는 의미이다. 이를 다르게 보면 다음의 조합과도 같다.

```
cd /
cd bin
````

즉, /를 통해 디렉토리를 연결해볼 수 있다. ~는 자신의 홈 디렉토리로의 이동이다. 또한 .과 ..을 유심히 볼 필요가 있다. 우리는 /와 ~를 이야기할 때 어느 특정 절대값만을 이야기했다. 디렉토리의 주소의 절댓값말이다. 근데 .과 ..은 상대적인 디렉토리의 값을 보여준다. 즉, 내가 지금 /Users/gms 에 위치해 있다면 .은 /Users/gms 를 의미한다. 

..은 무엇일까? 현재 위치에서의 부모 디렉토리 즉, /Users/gms 입장에서는 /Users 가 된다. 이 두 개를 통해 다양한 것들을 움직여볼 수 있다. 예를 들면 다음처럼

```
cd ../gms/../Users/./gms/./gms
```

이렇게 하면 /Users/gms 로 이동한다. 이렇게만 보면 장난치는 것만 같지만 실은 꽤나 중요한 역할을 맡고 있다. .은 자신의 디렉토리를 축약해서 처리할 수 있고, ..은 자신의 부모 디렉토리를 상대적으로 축약해서 처리할 수 있게 해준다. 

이쯤 돼서 셸이 이것들을 어떻게 처리하는지 궁금해진다. 그 전에 터미널부터 말하고 가야 한다. 터미널은 입력과 출력을 담당한다. 그 외에도 색깔 처리에 대한 해석도 담당하긴 한다. 어찌 됐든 입력된 내용을 커널의 PTY(pseudoterminal, 수도터미널)로 연결해준다. 여담이지만 이전에는 터미널이라는 것 자체가 하드웨어였고 현재는 가상의 터미널로 변경되면서 이름이 가상의 터미널을 뜻하는 수도터미널로 지어졌다고 한다.

어찌 됐든 PTY로 전달된 명령은 다시 셸에게 전달된다. 셸은 이 명령을 받고 어떻게 처리할 것인지 내부적으로 해석한다. 이때 사용되는 것이 $PATH이다. 이는 일종의 즐겨찾기 같은 것으로, 특정 디렉토리 위치들을 여기에 저장해두고 쓰는 방식이다. 여기에 date 명령이 저장된 파일의 부모 디렉토리인 /bin 도 저장돼 있다.

셸에 들어온 명령을 어떻게 처리할지 정했으면 그 다음으로는 커널에 이 명령을 전달하거나 시스템 콜한다. 명령이 실행된 뒤에는 프로그램 출력이 다시 PTY로 향하고, 터미널 출력으로 이어진다. 추후에 더 다루게 될 운영체제와의 연관이 깊어 더 깊게 파보지는 않았다. 지금은 강의에 일단 집중해보고 이번 강의가 끝나면 가볍게라도 찍먹해보려고 한다. 

그럼 셸 말고 자바나 파이썬은 이런 처리가 불가능할까? 가능하다. 셸도 자바, 파이썬과 같은 언어이며 이를 해석해주는 인터프리터도 존재한다. 셸이 다른 점은 커널의 명령어를 인간이 건드릴 수 있게 도와준다는 점이다.

자바, 파이썬도 똑같이 커널에 있는 명령을 쓸 수는 있지만 직접 함수를 작성해 처리해야 한다. 반면, 셸은 이를 간단하게 cd, date 등으로 축약한다 .이 과정에서 내부 명령과 파일로 저장하는 등의 추가적인 처리도 한 것으로 보인다. 이런 점에서 셸은 운영체제의 명령을 처리하기 위해 커널을 직접 건드리는 역할을 맡고 있음을 보인다.

커널의 의미인 '알맹이'를 셸의 의미인 '껍질'이 적절히 보호하고 인간이 사용하기 편하게 해준다는 의미가 명확히 드러난다.
