프로그램들은 서로 이어붙여 쓸 수 있다. 별도로 직접 치기에는 준비된 것이 없기에 예제를 그대로 가져다 쓰겠다.

```
missing:~$ ssh myserver 'journalctl -u sshd -b-1 | grep "Disconnected from"' \
  | sed -E 's/.*Disconnected from .* user (.*) [^ ]+ port.*/\1/' \
  | sort | uniq -c \
  | sort -nk1,1 | tail -n10 \
  | awk '{print $2}' | paste -sd,
postgres,mysql,oracle,dell,ubuntu,inspur,test,admin,user,root
```

ssh를 통해 서버에서 어떤 사용자가 접속이 끊겼는지에 대해 알아오는 명령어다. 이때 주의를 집중해야 할 부분은 바로 \| 이다. 이것은 파이프라고 부른다. 파이프의 역할은 뒤에 나올 명령어의 입력에 앞에 나오는 명령어의 출력을 넣어주는 데에 있다. 일단 ssh는 지금 당장 다루기에는 범위가 너무 넓으므로 잠시 뒤로 미루고 핵심이 되는 부분만 끊어서 보자. 

`ssh myserver '~~'`는 myserver 라는 서버에 ssh를 통해 접속해서 따옴표 안에 있는 명령을 실행하고 나온다. 실행 결과는 이 명령어를 입력한 컴퓨터에 나온다.  `journalctl -u sshd -b-1`이 명령어는 배우지는 않았지만 systemd 시스템의 로그를 보는 명령어이다. 그 뒤에 나오는 `| grep "Disconnected from"`은 앞선 출력인 시스템 로그를 받아 grep의 입력으로 처리한다. 즉, 로그에서 "Disconnected from" 이라는 문장을 찾는다. 찾아낸 줄마다 다시 그 출력이 sed로 들어가고, sed는 이를 입력으로 받는다.

정규식을 잘 모르지만 `sed -E 's/.*Disconnected from .* user (.*) [^ ]+ port.*/\1/' \`는 사용자 이름으로 바꾼다는 뜻이다. 즉, "... Disconnected from invalid user admin 1.2.3.4 port 22 [preauth]" 같은 문장에서 user의 이름인 admin만 떼서 편집해서 출력하게 된다. 이는 다시 `sort`로 입력이 들어가 정렬해 출력하고, `uniq -c`로 입력이 들어가 중복을 제거한 뒤 옆에 숫자를 표시해준다. 

이런 식으로 파이프는 앞선 출력을 다음의 입력으로 사용하는 데 쓰인다. 이것뿐만 아니라, \> 과 \<, \>\>도 존재한다. 이들은 리다이렉션이라고 부르며 앞선 파이프는 출력을 하고 그 출력을 다시 입력으로 사용했다면, 리다이렉션은 그 이름의 뜻처럼 출력할 내용을 그대로 파일의 입력으로 넣어버린다. 따라서 터미널에는 어떤 것도 출력되지 않는다. 예를 들면 다음과 같이 쓸 수 있다.

```
date >thedate.txt
```

date로 나온 오늘 날짜의 출력을 터미널로 표기하기 전 thedate.txt의 입력으로 넣고 파일로 저장한다. 대신 \>는 덮어쓰기이므로 연달아붙이기가 안 된다. 이럴 때는 \>\>를 통해 해결할 수 있다. 이는 다음 줄에 연달아 붙이는 기능이다. 따라서 앞선 thedate.txt에 2026/11/27 08:12 이 저장돼 있다가 1분 후에 다음과 같이 작성하게 되면,

```
date >>thedate.txt
```

결과는 `2026/11/27 08:12\n 2026/11/27 08:13` 처럼 2줄로 나오게 된다. \<는 뒤에 나오는 파일 내용을 앞에 있는 명령의 입력으로 쓰게 만든다. 그래서 

```
cat <thedate.txt
```
처럼 작성하게 됐을 때는 thedate.txt 내용을 출력하게 된다.

여기까지는 파이프와 리다이렉션에 대한 이야기였다. 그렇다면 어째서 이런 게 가능한 걸까? 비밀은 파일 디스크립터에 있다. 파일 디스크립터는 운영체제가 파일을 다룰 때 쓰는 정수 번호로, 기본적으로 프로세스를 시작했을 때 0, 1, 2를 받는다. 0번은 표준 입력(stdin), 1번은 표준 출력(stdout), 2번은 표준 에러(stderr)이다. 표준 입력은 기본적으로 키보드, 표준 출력과 표준 에러는 기본적으로 터미널 화면으로 연결돼 있다. 

파이프는 이런 점을 이용했다. 파이프 앞에 나오는 프로그램의 프로세스는 1번을 터미널 화면이 아닌 파이프의 입력으로,  파이프 뒤에 나오는 프로그램의 프로세스에서는 0번을 파이프의 출력으로 셸이 바꾸게 된다. 따라서 파이프가 마치 통로처럼 두 프로그램을 이어주는 것처럼 보이게 된다. 유닉스는 기본적으로 모든 입출력 가능한 개체들을 파일로 봤기 때문에 이런 방식을 사용할 수 있던 것이다.
